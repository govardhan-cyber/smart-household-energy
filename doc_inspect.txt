INTRODUCTION 1.1 Problem Statement In modern residential sectors, electrical energy costs represent a significant portion of household monthly expenses. However, domestic consumers face a severe asymmetry of information. Standard utility bills only present aggregated raw numbers (e.g., total energy consumed in kWh and total amount due) without dissecting where and how this power is utilized. Consumers lack clarity on slab-wise tariff charges, fixed meter fees, and taxes added by State Distribution Companies (DISCOMs). Additionally, manual calculation of daily appliance loads and evaluating the feasibility of transitioning to renewable energy resources (such as solar rooftop panels) requires complex computations and mathematical formulas that the average homeowner cannot calculate easily. Existing energy monitoring systems are either expensive IoT-based hardware devices or static utility portals that lack custom tariff modeling, personalized scheduling advice, and responsive user interfaces. 1.2 Project Objective The primary objective of the Smart Household Energy Manager project is to develop a highly interactive, accessible, and premium web-based dashboard application. This software empowers users to upload utility bills for automated analysis, perform granular audit logs of individual appliance consumptions, simulate rooftop solar ROI metrics, and ask an integrated AI chatbot questions about energy conservation. Crucially, the system features a custom DISCOM Tariff editor, letting users adjust slab definitions in real-time to align with regional electricity board rates. The user interface prioritizes high-fidelity visual aesthetics (such as glassmorphism, responsive data grids, and smooth state animations) to lower the cognitive barrier and encourage user engagement. 1.3 Scope of the Project The scope of this project includes the design, implementation, and deployment of a client-side single-page application built using React, Vite, TypeScript, and Tailwind CSS. The features comprise: User Authentication: Modern login and registration screens, secured with Firebase Auth, featuring animated background decorative particles. Interactive Energy Dashboard: Main hub featuring an animated sliding tab selector to switch between the Home Audit Wizard, Solar ROI Calculator, and AI Home Audit. AI Home Audit: Interactive step-by-step audit wizard where users select household appliances, simulate consumption, and view a visual circular SVG score gauge and count-up timer. Solar ROI Planner: Calculator providing solar size tables, modules required, financial payback indicators, and an interactive 3D roof preview rendered dynamically on a canvas. Bill Analyzer: System to upload and unpack utility bills. It parses data into 7 visual cards covering consumer metadata, billing readings, charge breakdown charts, carbon footprint gauges, and personalized saving tips. DISCOM Slab Editor: Administration panel allowing users to create, delete, and synchronize electricity tariff slabs directly with a Cloud Firestore database. AI Chatbot: A voice-and-text conversation interface using natural language processing to deliver personalized energy recommendations.                                  2. CHALLENGES FACED Several technical challenges were addressed during the engineering process: State Syncing and Re-renders: Storing tariff parameters in the root context meant that updating a slab rule could trigger cascade re-renders across the dashboard, causing input lag. This was resolved by using debounced state updates in the tariff editor. Responsive Table Design: Traditional HTML tables presenting solar system capacities overflowed on mobile devices. We refactored these into flex-grid cards that stack vertically on mobile and stretch horizontally on wide monitors. CSS Color Configuration: Encountered a design bug where settings wrapper containers would not adjust correctly during dark mode toggles. Ripgrep searches isolated typo classes (`slate-955` instead of `slate-950`). We resolved this by explicitly mapping custom color bounds in the Tailwind configuration file. TypeScript Interface Safety: Managing dynamic slab objects (where elements are added or deleted from lists dynamically) required strict TypeScript types to prevent compilation crashes during database transfers.  9. CHALLENGES FACED Several technical challenges were addressed during the engineering process: State Syncing and Re-renders: Storing tariff parameters in the root context meant that updating a slab rule could trigger cascade re-renders across the dashboard, causing input lag. We refactored these into flex-grid cards that stack vertically on mobile and stretch horizontally on wide monitors. CSS Color Configuration: Encountered a design bug where settings wrapper containers would not adjust correctly during dark mode toggles. Ripgrep searches isolated typo classes (`slate-955` instead of `slate-950`). We resolved this by explicitly mapping custom color bounds in the Tailwind configuration file. TypeScript Interface Safety: Managing dynamic slab objects (where elements are added or deleted from lists dynamically) required strict TypeScript types to prevent compilation crashes during database transfers.  9.
